# Computer Networks

Accenture tests networking, security and cloud with 10 questions in the written round. In interviews, **"what happens when you type google.com"** and **TCP vs UDP** are close to guaranteed.

---

## The OSI model — 7 layers

Remember top-down: **A**ll **P**eople **S**eem **T**o **N**eed **D**ata **P**rocessing.

| # | Layer | Job | Unit | Devices / protocols |
|---|---|---|---|---|
| 7 | **Application** | user-facing services | data | HTTP, FTP, SMTP, DNS |
| 6 | **Presentation** | translation, encryption, compression | data | SSL/TLS, JPEG |
| 5 | **Session** | establishes and manages sessions | data | NetBIOS, RPC |
| 4 | **Transport** | end-to-end delivery, reliability | **segment** | **TCP, UDP** |
| 3 | **Network** | logical addressing, routing | **packet** | **IP**, ICMP · **router** |
| 2 | **Data Link** | physical addressing, error detection | **frame** | MAC, ARP · **switch, bridge** |
| 1 | **Physical** | bits over the medium | **bit** | cables · **hub, repeater** |

> **Know the unit and the device for each layer** — that is what MCQs test. Router = layer 3,
> switch = layer 2, hub = layer 1.

## OSI vs TCP/IP

| | OSI | TCP/IP |
|---|---|---|
| Layers | 7 | 4 (Application, Transport, Internet, Network Access) |
| Nature | theoretical reference model | practical, implemented |
| Developed | after the protocols existed | protocols came first |

TCP/IP merges OSI's application, presentation and session into one **Application** layer, and physical plus data link into **Network Access**.

## TCP vs UDP — memorise this table

| | TCP | UDP |
|---|---|---|
| Connection | connection-oriented | connectionless |
| Reliability | guaranteed delivery, acknowledgements | best-effort, no guarantee |
| Ordering | preserves order | no ordering |
| Speed | slower | **faster** |
| Header size | 20 bytes | **8 bytes** |
| Flow / congestion control | yes | no |
| Error handling | retransmits | discards |
| Used by | HTTP, HTTPS, FTP, SMTP, SSH | DNS, DHCP, video streaming, VoIP, online games |

**The rule of thumb:** TCP when every byte must arrive (a file, a web page); UDP when lateness is worse than loss (a live call).

## The three-way handshake

How TCP opens a connection:

```
  Client                    Server
     │ ──── SYN (seq=x) ────→ │
     │ ←── SYN-ACK ────────── │   (seq=y, ack=x+1)
     │ ──── ACK (ack=y+1) ──→ │
     │      connection established
```

1. **SYN** — client requests a connection with its initial sequence number
2. **SYN-ACK** — server acknowledges and sends its own sequence number
3. **ACK** — client acknowledges the server's

**Connection termination is a four-way handshake** (FIN, ACK, FIN, ACK) — because each side closes its direction independently.

## What happens when you type google.com

This is the interview's favourite integrative question. Answer it as a sequence:

1. **Browser cache check** — has this been resolved recently?
2. **DNS resolution** — browser cache → OS cache → hosts file → recursive resolver → root
   server → `.com` TLD server → Google's authoritative name server → returns the IP.
3. **ARP** — resolves the next hop's IP to a MAC address for local delivery.
4. **TCP three-way handshake** with the server on port 443.
5. **TLS handshake** — certificate exchange, key agreement, encryption established.
6. **HTTP GET request** is sent.
7. **Server responds** with HTML, plus status code 200.
8. **Browser renders**: parses HTML, builds the DOM, requests CSS/JS/images, paints.

Mentioning DNS, TCP, TLS and rendering in order is what they are checking.

## IP addressing

**IPv4** — 32 bits, four octets (192.168.1.1). About 4.3 billion addresses.  
**IPv6** — 128 bits, hexadecimal (2001:0db8::7334). Vastly larger space, built-in IPsec, no need for NAT.

### Classes

| Class | First octet | Default mask | Use |
|---|---|---|---|
| A | 1–126 | /8 (255.0.0.0) | very large networks |
| B | 128–191 | /16 (255.255.0.0) | medium networks |
| C | 192–223 | /24 (255.255.255.0) | small networks |
| D | 224–239 | — | multicast |
| E | 240–255 | — | experimental |

127.x.x.x is reserved for **loopback** (127.0.0.1 = localhost).

### Private ranges (not routable on the internet)

- 10.0.0.0 – 10.255.255.255
- 172.16.0.0 – 172.31.255.255
- 192.168.0.0 – 192.168.255.255

### Subnetting

For a /26 mask (255.255.255.192):
- Host bits = 32 − 26 = 6 → 2⁶ = 64 addresses per subnet
- **Usable hosts = 64 − 2 = 62** (one network address, one broadcast address)

> **Usable hosts = 2^(host bits) − 2.** The −2 is asked constantly.

## Key protocols and ports

| Protocol | Port | Purpose |
|---|---|---|
| FTP | 20/21 | file transfer |
| SSH | 22 | secure shell |
| Telnet | 23 | remote login (insecure) |
| SMTP | 25 | sending mail |
| DNS | 53 | name → IP resolution |
| DHCP | 67/68 | automatic IP assignment |
| HTTP | 80 | web |
| POP3 | 110 | retrieving mail (downloads and deletes) |
| IMAP | 143 | retrieving mail (keeps on server, syncs) |
| HTTPS | 443 | web over TLS |

**HTTP vs HTTPS** — HTTPS is HTTP over SSL/TLS: encrypted, authenticated by a certificate, port 443 rather than 80. HTTP is stateless; **cookies and sessions** add state.

**DNS** — translates domain names to IP addresses. Uses **UDP** port 53 for queries (small and fast) and TCP for zone transfers and large responses.

**DHCP** — assigns IP addresses automatically. The handshake is **DORA**: Discover, Offer,  
Request, Acknowledge.

**ARP** — resolves an IP address to a MAC address. **RARP** does the reverse.

**ICMP** — error reporting and diagnostics; used by `ping` and `traceroute`.

## Devices

| Device | Layer | What it does |
|---|---|---|
| **Hub** | 1 | broadcasts to all ports; one collision domain; obsolete |
| **Switch** | 2 | forwards by MAC address; each port its own collision domain |
| **Router** | 3 | forwards between networks by IP; separates broadcast domains |
| **Bridge** | 2 | connects two LAN segments |
| **Gateway** | all | connects networks using **different protocols**; translates |

> **Router vs gateway** — a router connects networks using the *same* protocol; a gateway
> translates between *different* ones. Every gateway routes, not every router is a gateway.

## Topologies

| Topology | Strength | Weakness |
|---|---|---|
| **Bus** | cheap, simple | one cable fault kills the network |
| **Star** | easy to manage, fault isolation | central hub/switch is a single point of failure |
| **Ring** | no collisions, predictable | one break can stop the ring |
| **Mesh** | highly reliable, redundant paths | expensive, complex cabling |
| **Tree / hybrid** | scalable | complex |

**Network types:** **LAN** (a building), **MAN** (a city), **WAN** (a country or the globe;  
the internet is a WAN), **PAN** (personal, e.g. Bluetooth).

## Delays and security

**Four types of delay:** transmission (packet size ÷ bandwidth), propagation (distance ÷ speed), queuing (waiting at routers), processing (header inspection).

**Bandwidth vs latency** — bandwidth is how much data per second; latency is how long one packet takes to arrive. High bandwidth with high latency is normal (a satellite link).

**Firewall** — filters traffic against rules; may be packet-filtering, stateful, or application-level.

**VPN** — an encrypted tunnel over a public network, giving privacy and remote access to a private network. Cost: some latency.

**Symmetric vs asymmetric encryption** — symmetric uses one shared key (fast, e.g. AES);  
asymmetric uses a public/private key pair (slower, e.g. RSA). TLS uses asymmetric to exchange a symmetric key, then symmetric for the session.

## Full question bank

### Models and layers

**Why is a layered architecture used at all?**  
Each layer serves the one above and uses the one below, so a layer's implementation can change without affecting the others. It also lets vendors build interoperable pieces independently.

**What does each OSI layer actually do — one line each?**
- **Physical** — transmits raw bits; defines voltages, cables, pin layouts
- **Data Link** — framing, MAC addressing, error detection (CRC), flow control between
  adjacent nodes
- **Network** — logical addressing and routing across networks
- **Transport** — end-to-end delivery, segmentation, reliability, flow and congestion control
- **Session** — establishes, manages and terminates sessions; checkpointing
- **Presentation** — translation, encryption, compression
- **Application** — protocols the user's software speaks

**Which layers do a router, switch, hub, bridge, repeater and gateway work at?**  
Repeater and hub → **layer 1**. Bridge and switch → **layer 2**. Router → **layer 3**.  
Gateway → potentially **all layers** (it translates between protocol stacks).

**What is encapsulation in networking?**  
Each layer adds its own header (and sometimes trailer) to the data from the layer above:  
data → segment → packet → frame → bits.

### TCP, UDP and the transport layer

**What is in a TCP header that a UDP header lacks?**  
Sequence number, acknowledgement number, window size, and the flag bits (SYN, ACK, FIN, RST,  
PSH, URG) — all the machinery for reliability and flow control. Hence 20 bytes vs 8.

**What is flow control vs congestion control?**  
**Flow control** stops a fast sender overwhelming a slow *receiver* — handled by the sliding window. **Congestion control** stops senders overwhelming the *network* — handled by slow start, congestion avoidance, fast retransmit and fast recovery.

**What is the sliding window protocol?**  
The sender may have up to *window size* unacknowledged bytes in flight. The window advances as acknowledgements arrive, keeping the link busy without flooding the receiver.

**Stop-and-wait vs Go-Back-N vs Selective Repeat?**
- **Stop-and-wait** — one frame at a time; simple, very inefficient
- **Go-Back-N** — send N frames; on an error, retransmit that frame **and everything after**
- **Selective Repeat** — retransmit **only** the damaged frame; needs receiver buffering

**Why is connection termination four-way and not three-way?**  
TCP is full duplex, so each direction must be closed separately. One side sends FIN and gets  
ACK, then the other side does the same when it is ready.

**What is the TIME_WAIT state?**  
After closing, a socket waits (typically 2× the maximum segment lifetime) to make sure the final ACK arrived and no stray duplicate segments from this connection reappear.

**What is a socket?**  
The endpoint of a bidirectional connection, identified by **IP address + port number**. A connection is uniquely identified by the four-tuple (source IP, source port, destination IP, destination port).

**What is a port and what are the ranges?**  
A 16-bit number identifying an application. **0–1023** well-known, **1024–49151** registered, **49152–65535** dynamic/ephemeral.

### IP, routing and addressing

**What is subnetting and why do it?**  
Splitting one network into smaller logical networks by borrowing host bits for the network portion. It reduces broadcast domains, improves security and uses address space efficiently.

**Worked example: how many subnets and hosts from 192.168.1.0/24 using /27?**
- Borrowed bits = 27 − 24 = 3 → 2³ = **8 subnets**
- Host bits = 32 − 27 = 5 → 2⁵ − 2 = **30 usable hosts per subnet**

**What is CIDR?**  
Classless Inter-Domain Routing — abandons rigid A/B/C classes and uses an explicit prefix length (192.168.1.0/26), allowing arbitrarily sized allocations and route aggregation.

**What is NAT and why is it needed?**  
Network Address Translation maps private addresses to one or a few public addresses. It conserves scarce IPv4 addresses and incidentally hides the internal topology.

**What is a subnet mask, network address and broadcast address?**  
The **mask** separates network bits from host bits. The **network address** has all host bits  
0; the **broadcast address** has all host bits 1. Neither is assignable to a host — hence the  
−2.

**What is the default gateway?**  
The router a host sends packets to when the destination is outside its own subnet.

**Static vs dynamic routing?**  
**Static** routes are configured manually — predictable, no overhead, but no failover.  
**Dynamic** routing protocols discover and adapt automatically.

**Name the routing protocols and their type.**
- **RIP** — distance vector, hop count metric, max 15 hops
- **OSPF** — link state, uses Dijkstra, fast convergence, within an organisation
- **BGP** — path vector, routes **between** autonomous systems; the routing protocol of the
  internet

**Distance vector vs link state?**  
Distance vector routers share their whole routing table with neighbours only ("routing by rumour"); slower convergence and count-to-infinity problems. Link state routers flood link information to everyone and each computes the whole topology — faster and loop-free, but more  
CPU and memory.

**What is TTL and what is it for?**  
Time To Live, a field decremented by each router. At zero the packet is discarded and an ICMP message returned. It prevents packets circulating forever in a routing loop, and it is what  
`traceroute` exploits.

**What is MTU and fragmentation?**  
Maximum Transmission Unit — the largest frame a link can carry (1500 bytes on Ethernet).  
Larger IP packets are fragmented and reassembled at the destination. IPv6 does not fragment in routers; the source must discover the path MTU.

### Application layer

**Describe the DNS resolution process.**  
Browser cache → OS cache → hosts file → configured recursive resolver. If uncached, the resolver queries a **root** server, which refers it to the **TLD** server (.com), which refers it to the **authoritative** name server for the domain, which returns the record. The resolver caches the answer for the TTL.

**What are the DNS record types?**  
**A** (IPv4), **AAAA** (IPv6), **CNAME** (alias), **MX** (mail server), **NS** (name server),  
**TXT** (arbitrary text, used for SPF/verification), **PTR** (reverse lookup).

**Recursive vs iterative DNS query?**  
In a **recursive** query the server must return a final answer, doing the work itself. In an  
**iterative** query it returns the best referral it has and the client continues.

**HTTP methods and what they mean?**  
**GET** (retrieve, safe and idempotent), **POST** (create/submit, not idempotent), **PUT** (replace, idempotent), **PATCH** (partial update), **DELETE** (remove, idempotent), **HEAD** (headers only), **OPTIONS** (supported methods).

**GET vs POST?**  
GET puts parameters in the URL (visible, length-limited, cacheable, bookmarkable); POST puts them in the body (not logged in URLs, no practical length limit, not cached). Neither is encrypted without HTTPS.

**What are the HTTP status code classes?**  
**1xx** informational, **2xx** success (200 OK, 201 Created), **3xx** redirection (301 permanent, 302 temporary, 304 Not Modified), **4xx** client error (400, 401 Unauthorized,  
403 Forbidden, 404, 429 Too Many Requests), **5xx** server error (500, 502, 503).

**401 vs 403?**  
**401 Unauthorized** — you have not authenticated (or your credentials failed).  
**403 Forbidden** — you are authenticated but not permitted.

**Why is HTTP called stateless, and how is state added?**  
Each request is independent; the server keeps no memory of previous ones. State is added with  
**cookies** (stored client-side), **sessions** (an ID in a cookie referencing server-side state), and tokens (JWT).

**How does the TLS handshake work?**  
Client hello (supported ciphers) → server hello with its **certificate** → the client validates the certificate against a trusted CA → key exchange establishes a shared symmetric key → both switch to symmetric encryption for the session.

**What is a digital certificate and who issues it?**  
A document binding a public key to an identity, signed by a **Certificate Authority**. The browser trusts it because it trusts the CA's root certificate.

**Difference between HTTP/1.1, HTTP/2 and HTTP/3?**  
HTTP/1.1 is text-based with one request at a time per connection (head-of-line blocking).  
**HTTP/2** is binary with multiplexing and header compression. **HTTP/3** runs over **QUIC (UDP)**, removing transport-level head-of-line blocking.

**FTP vs SFTP vs TFTP?**  
FTP uses two connections (control 21, data 20) and is unencrypted. **SFTP** runs over SSH (port 22), encrypted. **TFTP** is a minimal UDP-based version (port 69) with no authentication.

**POP3 vs IMAP?**  
POP3 downloads and typically deletes from the server — one device. IMAP keeps mail on the server and synchronises state across many devices.

### Security

**Symmetric vs asymmetric encryption — and why use both?**  
Symmetric (AES) is fast but requires securely sharing the key. Asymmetric (RSA) solves key distribution but is slow. TLS uses asymmetric to agree on a symmetric key, then symmetric for the bulk data.

**What is hashing and how does it differ from encryption?**  
Hashing is **one-way** and fixed-length (SHA-256) — used for integrity and password storage.  
Encryption is **reversible** with a key.

**What is a digital signature?**  
The sender hashes the message and encrypts the hash with their **private** key. Anyone can decrypt it with the public key and compare hashes — proving authenticity, integrity and non-repudiation.

**Common attacks worth naming:**
- **DoS / DDoS** — flooding a service until it cannot serve legitimate users
- **Man-in-the-middle** — intercepting and possibly altering traffic between two parties
- **ARP spoofing** — forging ARP replies to redirect LAN traffic
- **DNS spoofing / cache poisoning** — feeding a resolver a false record
- **SQL injection** — injecting SQL through unsanitised input
- **XSS** — injecting scripts that run in another user's browser
- **Phishing** — deceiving a user into surrendering credentials

**Firewall types?**  
**Packet filtering** (inspects headers only, stateless), **stateful inspection** (tracks connection state), **proxy / application-level** (inspects payloads and terminates the connection).

**What is a VPN and what does it actually protect?**  
An encrypted tunnel over a public network. It protects traffic in transit from the local network and ISP, and lets a remote user appear to be inside a private network. It does not make you anonymous to the destination.

### Cloud (Accenture asks this)

**IaaS vs PaaS vs SaaS?**
- **IaaS** — you rent raw infrastructure (VMs, storage): AWS EC2, Azure VMs
- **PaaS** — you deploy code onto a managed platform: Heroku, App Engine
- **SaaS** — you use finished software: Gmail, Salesforce

**Public, private, hybrid and community cloud?**  
Public — shared, provider-owned. Private — dedicated to one organisation. Hybrid — a mix, with workloads moving between them. Community — shared by organisations with common concerns.

**What is virtualisation, and a VM vs a container?**  
Virtualisation runs multiple isolated environments on one physical machine. A **VM** includes a full guest OS on a hypervisor — heavier, stronger isolation. A **container** shares the host kernel — lighter, faster to start, less isolated (Docker).

**What is load balancing?**  
Distributing incoming traffic across several servers to improve throughput and availability.  
Strategies: round robin, least connections, IP hash.

## Traps

- Router is layer 3, switch is layer 2, hub is layer 1. Do not mix them up.
- The unit at the transport layer is a **segment**, at network a **packet**, at data link a
  **frame**.
- DNS uses **UDP** for ordinary queries, not TCP.
- Subnet usable hosts is 2ⁿ **− 2**.
- Termination is **four**-way, not three-way.
- POP3 downloads and deletes; IMAP syncs and keeps. They are not interchangeable.
- HTTPS is port 443, not 80.
