# OBSERVATION BANK

When you read an editorial, you extract **exactly one sentence**: the key observation. Not the approach. Not the code. The single insight that, if you'd had it, would have unlocked the problem.

**Read this whole file for 5 minutes before every mock.**

By Week 8 this should hold ~80 sentences and be the most valuable page you own.

## Rules

- One sentence. If it takes three, you haven't found the observation yet — you've found the solution.
- Write it so it makes sense in isolation, months later, without the problem in front of you.
- Good: *"Only elements that are the start of a run need to be walked, and x is a start iff x−1 is absent."*
- Bad: *"Use a HashSet and loop."* (That's a technique, not an observation.)
- Good: *"Fixing the split point turns a two-sided transformation cost into two independent prefix/suffix scans."*
- Bad: *"It's a DP problem."*
